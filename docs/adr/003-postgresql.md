# Почему PostgreSQL

## Суть

Нужно было выбрать СУБД. Рассматривала PostgreSQL, MySQL, H2 и MongoDB.

## Что я выбрала и почему

Выбрала PostgreSQL 16.

Финансовые данные требуют строгой консистентности — мне нужны полноценные ACID-транзакции с нормальными уровнями изоляции. PostgreSQL это обеспечивает надёжно.

Домен проекта (пользователи, семьи, участники, транзакции, категории) естественно ложится на реляционную модель с внешними ключами и ограничениями целостности. Попытка уложить это в документную модель (MongoDB) привела бы к дублированию данных и проблемам с консистентностью.

PostgreSQL позволяет создать несколько баз на одном сервере — я завела `auth_db` и `finance_db` для логической изоляции данных между сервисами.

У PostgreSQL зрелая поддержка во всём стеке: Spring Data JPA, Flyway, Testcontainers, Docker. Всё работает из коробки.

H2 я использую только в тестовом окружении как fallback — для production она не подходит.

## Итог

PostgreSQL — надёжная СУБД для финансовых данных с ACID-гарантиями и хорошей интеграцией со Spring. Для запуска используется Docker Compose, а в интеграционных тестах — Testcontainers с реальным PostgreSQL.
